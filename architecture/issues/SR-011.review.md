# SR-011: Rebuild Client Rendering from Network Components

## Objective

Make the client render mirrored server entities using network components, without relying on serialized draw callbacks.

## Scope

- Keep the canvas render pipeline client-side.
- Rebuild draw statements locally from network components.
- Render server-owned ships, asteroids, aliens, bullets, pickups, shields, health bars, lasers, rockets, and boomerangs.
- Read `GameStateView` for UI.
- Map fixed world coordinates to canvas coordinates.

## Dependencies

- `SR-002`
- `SR-004`

## Blocks

- `SR-012`
- `SR-014`

## Implementation Notes

- `Drawable` should sync sort data only, such as `zIndex`.
- Client systems can use enter/update hooks to attach local draw callbacks whenever relevant network components appear or change.
- `Shape`, `Arc`, `StrokeStyle`, `FillStyle`, and `FilledRect` provide enough data to reconstruct existing draw statements.
- Stars remain purely local.
- UI should not mutate game state; it only reads mirrored state.

## Acceptance Criteria

- Server-created renderable entities appear in the client.
- Rendering updates as network components change.
- Client does not require local gameplay factories to draw server entities.
- Client UI displays server-owned score/wave/status.
