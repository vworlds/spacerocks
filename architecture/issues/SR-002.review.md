# SR-002: Define Shared Vecs Network Schema

## Objective

Create the canonical shared network component schema used by both the vecs server and vecs client.

## Scope

- Define wire-encoded network components in `packages/common`.
- Export a single `NETWORK_COMPONENTS` array.
- Put `Position` first for vecs-client interpolation.
- Convert or replace current serializable components with vecs-wire decorated fields.
- Split network-safe component data from client runtime rendering callbacks.
- Add shared world constants such as `WORLD_WIDTH` and `WORLD_HEIGHT`.
- Add tests or compile-time checks that server/client import the same schema.

## Proposed Components

- `Position`: `x`, `y`.
- `Rotation`: `angle`.
- `Drawable`: `zIndex` only.
- `StrokeStyle`: color/style and line width.
- `FillStyle`: color/style.
- `Shape`: array of points.
- `Arc`: radius/start/end angles.
- `FilledRect`: width/height.
- `PlayerShip`: player index or display color metadata.
- `AsteroidView`: level/color/radius metadata.
- `ProjectileView`: projectile kind and owner/team metadata.
- `PickupView`: pickup kind and amount metadata.
- `HealthView`: hp/maxHp/bar timer if the client draws health bars.
- `ShieldView`: remaining shield time.
- `WeaponView`: active weapon and ammo counts visible to client.
- `GameStateView`: state, wave, score, status.
- `ExplosionView`: color, size, seed, duration.

## Implementation Notes

- Network component IDs are array-order based. Do not register network components ad hoc.
- Do not include functions in any network component.
- For arrays, use vecs-wire array field support with a wire-encodable `Point` class if needed.
- `Drawable` must not sync `_statements` or draw callbacks.

## Acceptance Criteria

- Server and client can import `NETWORK_COMPONENTS` from `@spacerocks/common`.
- Network components compile with vecs-wire encoding.
- `Position` is component type `1` in a `NetworkWorld`.
- Existing custom `ISerializable` can be left in place temporarily, but new code does not depend on it.
