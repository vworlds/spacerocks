# SR-006: Implement Multiplayer Player Session Ownership

## Objective

Create one server-owned ship per connected client and model ownership through relationships so cleanup cascades automatically.

## Scope

- Detect connected clients through `NetworkClient` entities.
- Create a ship for every connected client.
- Associate ship and owned entities with the client/session/player parent using `ChildOf` or a user-defined relationship.
- Destroy owned entities automatically when the parent is destroyed.
- Apply `NetworkInput` only to the owning player's ship.
- Assign spawn positions and player display colors.

## Ownership Rules

- Session/player entity is the root owner.
- Ship is child of session/player.
- Projectiles and boomerangs are children of ship or session/player.
- Disconnect destroys session/player and cascades to owned entities.
- Boomerang return/catch checks relationship parent, not object identity.

## Implementation Notes

- Use `NetworkClient.id` only as session metadata; do not expose transport IDs in gameplay if avoidable.
- Initial spawn can use simple round-robin positions.
- Preserve arbitrary player count. Do not hard-code two players.

## Acceptance Criteria

- Every client connection creates exactly one controlled ship.
- Multiple clients can connect and receive distinct ships.
- Each client controls only its own ship.
- Disconnect removes that client's ship and owned child entities.
