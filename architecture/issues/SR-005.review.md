# SR-005: Split and Move Gameplay Components and Constants

## Objective

Prepare the current client-only gameplay model for server authority by moving shared/server gameplay components and constants out of the browser client.

## Scope

- Move authoritative gameplay components to shared or server modules.
- Keep DOM/render-only components in the client.
- Introduce server-only components for simulation state.
- Replace function-valued components with enum/data components.
- Replace entity-reference fields with relationship ownership or stable IDs.
- Introduce fixed world-size constants.

## Implementation Notes

- `Pickup.effectFunc` should become `PickupKind` plus server-side effect handling.
- `RandomClock.effectFunc` should become data plus server-side spawn systems.
- `Boomerang.owner: Entity` should become a relationship to the owner ship or player.
- `BoomerangWeapon.shots` can remain data; `Set<Entity>` should not remain in a network/shared component.

## Acceptance Criteria

- Server code can import all authoritative gameplay components without importing DOM/client modules.
- Client render code can import render components without importing server-only simulation state.
- No server-bound component stores functions, DOM types, canvas types, `Entity`, or `Set<Entity>`.
