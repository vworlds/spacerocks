# SR-009: Move Shooting and Weapon Systems to Server

## Objective

Move all weapon firing, cooldowns, ammo, projectile creation, and projectile movement behavior to the server.

## Scope

- Migrate default bullets.
- Migrate aura weapon firing.
- Migrate laser weapon state.
- Migrate rocket creation and homing behavior.
- Migrate boomerang creation, return behavior, arming, and catch readiness.
- Attach owned projectiles to the owning ship/session through relationships.

## Dependencies

- `SR-005`
- `SR-006`
- `SR-007`

## Blocks

- `SR-010`

## Systems and Factories to Move

- `Shooting`
- `LaserSystem`
- `RocketSystem`
- `BoomerangSystem`
- `createBullet`
- `createRocket`
- `createBoomerang`

## Implementation Notes

- The client input payload has a semantic `shoot` boolean only.
- Cooldown is server-owned.
- Weapon ammo/state is server-owned and optionally mirrored through `WeaponView`.
- Projectiles should be `Networked` if they need to render directly.
- Owned projectiles should be children of the owner ship or player parent for disconnect cleanup.

## Acceptance Criteria

- Server creates bullets/rockets/boomerangs from player input.
- Weapon cooldown and ammo cannot be bypassed by client mutation.
- Clients render projectiles from server network state.
- Disconnect destroys active owned projectiles.
