# SR-003: Build Vecs Server Shell and Connection Lifecycle

## Objective

Replace the Colyseus server shell with a vecs-server shell that accepts WebRTC client connections and syncs at least one server-created entity.

## Scope

- Replace `apps/server/src/index.ts` Colyseus startup with Express + `VecsListener`.
- Create a `ServerWorld` named `main` using `NETWORK_COMPONENTS`.
- Add simulation, collect, and send phases.
- Install vecs server systems with `server.installSystems({ collectPhase, sendPhase })`.
- Start a fixed-rate simulation loop.
- Configure `View` for clients so they can see networked entities.
- Add a temporary server-created debug entity to verify sync.

## Implementation Notes

- The vecs demo uses `VecsListener.registerWorld(world)` and `vecsListener.listen(app, { ordered: false, maxRetransmits: 2 })`.
- Default world path is `/rtc/v1/world/:worldName`.
- Set `View.dsl = true` for initial implementation. Interest management can come later.
- Keep logging simple and preserve current `PORT` env behavior where possible.

## Acceptance Criteria

- Server starts without Colyseus.
- A `ServerWorld` progresses at a fixed rate.
- Connected clients receive networked entities when a matching client shell exists.
- Existing Colyseus `UniverseRoom` is no longer part of server startup.
