# SR-013: Rehome Tests and Add Authoritative Server Coverage

## Objective

Move existing gameplay coverage from client-only tests to server-authoritative tests and add integration coverage for vecs networking behavior.

## Scope

- Move or duplicate DOM-free gameplay tests into `apps/server/tests`.
- Add tests for migrated movement, wrapping, spawning, shooting, collision, health, score, and ownership cleanup.
- Add tests for network component registration order.
- Add client render tests with mocked mirrored entities.
- Update old client tests that assumed gameplay authority in the browser.

## Dependencies

- `SR-005`

## Blocks

- `SR-014`

## Test Areas

- Network schema order and `Position` type id.
- Player session creates exactly one ship.
- Disconnect destroys child-owned entities.
- Input changes only owning ship.
- Movement and wrapping match expected behavior.
- Shooting respects cooldown/ammo.
- Collision changes health/score/entities correctly.
- Waves spawn after clear.
- Pickup effects apply correctly.
- Explosion marker TTL expires.

## Implementation Notes

- Prefer direct `ServerWorld` tests for gameplay systems instead of full WebRTC tests where possible.
- Keep a small number of integration tests for client/server connection if test infrastructure supports it.
- Tests should assert that client-only systems do not mutate authoritative gameplay state.

## Acceptance Criteria

- `npm test` passes with server-authoritative gameplay tests.
- Old tests are either migrated, rewritten, or intentionally removed with equivalent coverage.
- `npm run typecheck` and `npm run lint` pass.
