# SR-010: Move Collision, Health, Score, Game State, and Death Handling to Server

## Objective

Complete authoritative gameplay by moving collision resolution, health/damage, scoring, game state, and death/restart handling to the server.

## Scope

- Migrate circle collision detection.
- Migrate collision registry/effects or replace with data-driven handlers.
- Migrate asteroid splitting and score updates.
- Migrate alien/player/projectile collision behavior.
- Migrate pickup application.
- Migrate shield and health behavior.
- Create and sync a server-owned `GameStateView` entity.
- Replace client `setTimeout` restart behavior with server-controlled game flow.

## Systems to Move

- `Collision`
- `HealthSystem`
- `ShieldSystem`
- Collision portions of `LaserSystem`
- Server-side score/wave/game-over logic

## Implementation Notes

- Preserve existing collision category/mask behavior initially.
- `Pickup.effectFunc` must be replaced with server-side handlers keyed by pickup kind.
- Server should create `ExplosionView` entities instead of calling client particle factories.
- Decide initial multiplayer death semantics explicitly. Recommended first pass: a player ship can die/respawn independently while global wave/score continues.

## Acceptance Criteria

- Collision outcomes are determined only on the server.
- Health, shield, score, wave, and state updates are server-owned.
- Clients receive game state through mirrored network components.
- Client no longer runs authoritative collision, health, shield, or score systems.
